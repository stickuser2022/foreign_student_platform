## 0. 站点拓扑

单域名,目录结构(不抄 CUCAS 的子域群):

```
/                    首页
/universities        学校列表(搜索/筛选)
/universities/[slug] 学校详情页
/programs/[id]       项目详情页
/scholarships        奖学金目录
/guides              攻略内容(CSC/CSCA/签证,俄语)
/sign-in /sign-up    认证
/favorites           我的收藏(需登录)
/profile             学生档案(需登录,渐进收集)
/admin               后台:录入 + 审核队列(仅 platform_admin)
```

i18n:【远期】`[locale]` 前缀路由(ru/zh/en),MVP 阶段界面硬编码俄语、后台中文。

## 8. 后台 `/admin`【自建,MVP 末段就做】

数据是平台的生命线,后台优先于一切花哨功能:

| 模块 | 说明 |
|---|---|
| 审核队列 | dataStatus=DRAFT 的记录列表 → 逐条确认/修改 → 置 PUBLISHED(AI 抽取管道的人工环节) |
| 学校/项目/奖学金录入表单 | 手工录入 + 将来的 AI 辅助填充 |
| 数据健康 | lastVerifiedAt 超过 N 个月的记录标黄提醒复核 |

权限:middleware 校验 user.role === "platform_admin"。

## 9. 功能排期总表

```
MVP:     P2 完善(筛选) → P3 学校详情(含费用速览卡) → P4 项目详情 → P5 奖学金 →
         收藏(P3/P4 ♡ + /favorites) → /admin 录入与审核队列
二期:    P1 首页改版 → P6 攻略内容 → /profile 渐进收集 → 对比工具(并排表格)
三期:    AI 对比解读、相似项目推荐、Review 证言体系、next-intl 多语言
远期:    申请系统(Application 6 态)、支付、iAgent 式渠道体系、profile 智能推荐
```

## 10. 全局设计原则(施工时不得违反)

1. 项目是原子单位;页面 = 模板 + 数据
2. 公开页面只渲染 PUBLISHED;可比较字段必须结构化、单位统一(人民币/年)
3. 门槛后置:浏览全免登录,注册钩子只在收藏/提醒处出现
4. 价格透明前置:费用出现在卡片和详情页顶部区域
5. 推荐辅助浏览,不替代浏览(防信息茧房,远期推荐功能也守这条)
6. 卢布只换算展示,永不入库
